# Security

This document maps each risk in the **OWASP Top 10 (2021)** to the controls in this codebase. Each control has a test in `tests/` that keeps it working.
No software is "100% secure". The aim is that every store you ship starts from a hardened baseline, and that CI catches regressions and newly published vulnerable dependencies.

| # | Risk | What Storefront does | Where |
|---|------|----------------------|-------|
| A01 | Broken Access Control | A blueprint-wide `before_request` login check covers every `/admin` route, so a forgotten decorator can't expose a page. Support tools are restricted to the `super` role (owners get 403, and attempts are logged), and the support account can't be edited from the web. State changes are POST only. Object IDs are checked against their parent (e.g. an image must belong to the product in the URL). Login redirects only accept local paths (no open redirect). Admin pages are `Cache-Control: no-store`. `/admin` is disallowed in robots.txt. | `admin/routes.py`, `auth.py`, `security.py` |
| A02 | Cryptographic Failures | Passwords are hashed with **scrypt** (werkzeug). The cross-store support password is only ever stored as a hash in env vars. Session cookies are `Secure`, `HttpOnly` and `SameSite=Lax` in production, and HSTS is set. `SECRET_KEY` is required in production and auto-generated by the Render Blueprint. No card data is ever handled; payment happens off-site. | `models.py`, `config.py`, `security.py`, `render.yaml` |
| A03 | Injection | All DB access goes through the SQLAlchemy ORM (parameterised). Jinja autoescaping is on, and no user/admin text is marked `safe`. The storefront JS writes with `textContent` only. Product data is embedded via `tojson`, which escapes `</script>`. Admin settings use **allow-list validation**: colours must be `#rrggbb`, fonts and currencies are chosen from fixed lists, links must be `https://` (blocks `javascript:`), and phone numbers are digits only. Email uses `EmailMessage`, which rejects header injection. | `settings_schema.py`, `site.js`, templates |
| A04 | Insecure Design | **Payments:** the browser sends only product ids, sizes and quantities, and the server recomputes every price. An order is marked paid only after Paystack confirms it (signed webhook or server-side verify), with the exact amount, currency and reference. Paid-but-mismatched transactions are flagged, never accepted. Checkout is rate-limited. Enquiries have a honeypot field and a per-IP limit (5/hour). Login has a per-IP limit (20 per 15 min) plus **account lockout** (5 failures → 15 min). Limits are stored in the DB, so they hold across all workers. Uploads are size-capped, image pixel counts are capped (decompression-bomb guard), and the cart re-reads prices from the server data, never from browser storage. | `security.py`, `public/routes.py`, `auth.py`, `media.py` |
| A05 | Security Misconfiguration | A strict **Content-Security-Policy** with per-request nonces (no `unsafe-inline`), plus `X-Frame-Options: DENY`, `frame-ancestors 'none'`, `nosniff`, `Referrer-Policy`, `Permissions-Policy` and COOP/CORP. The `Server` header is removed. Error pages are generic, with no stack traces. Debug mode refuses to start in production. `ALLOWED_HOSTS` blocks Host-header attacks. Uploads are never written to disk and never served as HTML or SVG. | `security.py`, `__init__.py`, `media.py` |
| A06 | Vulnerable & Outdated Components | All dependencies are pinned. CI runs `pip-audit` on every push **and weekly**, so a newly disclosed CVE fails the build. The only third-party asset is Google Fonts CSS, and only a fixed list of font names can be placed in its URL. | `requirements.txt`, `.github/workflows/ci.yml` |
| A07 | Identification & Authentication Failures | Passwords need 10+ characters and are checked against common passwords and the username. The login error is the same whether or not the account exists (no enumeration). The session is cleared on login (no fixation). Sessions expire after 8h. Changing the password rotates a per-user token that **signs out every other device**. The support (superadmin) login needs **TOTP 2FA**: production refuses it without 2FA, codes can't be replayed, and the second step is rate-limited and expires after 5 minutes. Flask-Login `session_protection="strong"` is enabled. | `auth.py`, `models.py` |
| A08 | Software & Data Integrity Failures | CSRF tokens on every form and on the JSON checkout (Flask-WTF). Paystack webhooks must carry a valid **HMAC-SHA512 signature** and are idempotent. Images are decoded and **re-encoded** by Pillow, which strips metadata (phone GPS) and anything that isn't pixels. Videos must have MP4/WebM magic bytes. `import-store` only accepts known setting keys and media types. CI runs with read-only `contents` permission. | `media.py`, `cli.py`, `ci.yml` |
| A09 | Security Logging & Monitoring Failures | Every sign-in (owner and support), failed sign-in or 2FA code, lockout, rate-limit hit, password change, support action, paid order, bad webhook signature and admin edit is written to an **audit log**, which the owner can see under *Admin → Security log*. It is also written to stdout, so it shows up in Render's logs. | `security.py` (`audit`), `admin/activity.html` |
| A10 | Server-Side Request Forgery | The server makes outbound requests only to the fixed Paystack API host over https. Paths are built from constants, and the one dynamic part (the order reference) is format-checked and URL-encoded. The Paystack redirect URL must be on `checkout.paystack.com`. It never fetches URLs supplied by users or admins. | `payments.py` |

## Operating a client store safely

- Give each client their **own** Render service and Neon database, so one store's data is never reachable from another.
- Set `ALLOWED_HOSTS` to the client's domain(s) and the `onrender.com` hostname.
- Generate your support login with `flask superadmin-setup` (16+ character password, 2FA). Keep the TOTP secret only in your authenticator app and in the stores' env vars.
- Use a long, unique `ADMIN_PASSWORD` for the first login and ask the client to change it under **Account**.
- Keep CI green. When the weekly `pip-audit` run fails, bump the flagged package, run the tests and redeploy every client.
- Neon keeps point-in-time restore; `flask export-store backup.json` gives you an extra off-site copy of the catalogue.

## Reporting a vulnerability

Email the maintainer rather than opening a public issue. Please include steps to reproduce.
